## 1. 背景与目标

### 1.1 背景

现有邮件客户端（Outlook、Thunderbird、Foxmail、Spark）在信息密度、排版、交互节奏上无法满足个人审美与使用习惯。本项目不以"功能更全"为目标，而是**以重构一个自己满意的邮件阅读界面为核心**，用最小可用功能支撑 UI 迭代。

因此产品本质是：**一个可完全掌控界面的本地邮件阅读器**，而非通用邮件客户端。

### 1.2 产品目标

1. 提供一个可长期自用、界面完全自主设计的 Windows 桌面邮件阅读器。
2. 只做"收信 + 阅读 + 整理"，把复杂度压到最低，让 90% 的工程量投入 UI/交互。
3. 同步内核与 UI 彻底解耦：UI 只用假数据也能完整开发，替换 UI 不影响同步层。

### 1.3 非目标（明确不做）

| 不做 | 原因 |
| --- | --- |
| 发送邮件（SMTP 发信、草稿、回复/转发） | 明确需求外；可后续以独立模块扩展 |
| 日历 / 联系人 / 任务 | 群件复杂度，与 UI 目标无关 |
| Exchange / EWS / Microsoft Graph / Gmail API | 只走 IMAP；降低协议与合规成本 |
| macOS / Linux / 移动端 | Windows 单平台，可用 Windows 专有能力（safeStorage、Toast） |
| 云同步、多设备、账号漫游 | 单机本地存储 |
| 插件系统、主题市场 | P2 之后再评估 |
| 商用、闭源、分发收费 | 开源非商用，GPL 兼容性不作为约束（但也尽量避免 GPL 依赖以便日后换协议） |

### 1.4 成功标准（可量化）

| 指标 | 目标值 |
| --- | --- |
| 冷启动到可交互 | < 1.5 s（SSD、i5 级以上） |
| 邮件列表滚动帧率 | 10,000 封下 ≥ 55 fps |
| 常驻内存 | < 350 MB（单账号、常驻托盘） |
| 样式改动反馈 | Vite HMR < 300 ms |
| 首次同步 2,000 封 | < 60 s（10 Mbps 以上） |
| 新增一个界面模块耗时 | < 30 min（模板化，shadcn 组件即取即用） |
| 阅读一封 5 MB HTML 邮件的渲染耗时 | < 300 ms |

## 2. 用户与场景

### 2.1 用户画像

单一用户：开发者本人。技术能力强，能自行配置 IMAP 参数、获取授权码、排查连接问题。**不需要**面向小白的引导式配置。

### 2.2 核心场景

| 编号 | 场景 | 频率 |
| --- | --- | --- |
| S1 | 开机后挂后台，收到新邮件时看到 Windows 通知 | 每日多次 |
| S2 | 打开应用，扫一眼未读列表，点开阅读 | 每日多次 |
| S3 | 切换多个邮箱账号（如 QQ + 自建域名）查看 | 每日 |
| S4 | 用关键词搜索历史邮件 | 每周 |
| S5 | 阅读带复杂排版的 HTML 邮件（营销、周报） | 每日 |
| S6 | 下载附件、预览图片 | 每周 |
| S7 | 断网状态下翻看已缓存邮件 | 偶尔 |

## 4. 信息架构与页面

### 4.1 主界面布局

采用 Mimestream 式三栏：**没有 App Rail、没有 Ribbon**，栏与栏之间不画分割线，只用背景明度分层（见 6.3）。

    ┌────────────────┬───────────────────────────┬──────────────────────────────┐
    │ ☰ 菜单 + 侧栏开关│ 文档页签栏（文件夹 / 邮件）+ 列表列头 │ 阅读器（无独立工具条）     │
    │ ─────────────  │ ───────────────────────── │ ──────────────────────────── │
    │ 文件夹 / 标签   │ 邮件列表 380px（320–窗口半）   │ 正文满宽 + 左右 24px 内边距    │
    │ 220px（可收起）│ 虚拟滚动，行高 26 / 60（三行 72） │ 上 20px / 下 16px 内边距       │
    │ 底部：设置 / 同步 │                           │                              │
    └────────────────┴───────────────────────────┴──────────────────────────────┘

- **标题栏左上角是 ☰ 菜单**（2026-11-27 用户要求，取 OpenCode 的样式）：账户切换与账户管理都收进这个菜单（列出所有账户并勾选当前账户，每行可编辑/删除，底部「添加账户…」直接打开新增表单），后面紧跟侧栏开关。标题栏不再有 220px 的账户胶囊左段，也不在标题栏单独显示当前账户名。
- 列表与正文之间那条 1px 分隔线就是拖拽把手：可拖范围 320px ~ **窗口宽度的一半**（上限随窗口缩放，窗口变窄时自动收回），宽度持久化，双击复位 380px；侧栏可整体收起（2026-11-27 用户要求，取代原来的 50px 图标态）：收起/展开是 200ms 的宽度动效（`prefers-reduced-motion` 下不做），侧栏内容不重排、只被裁掉；收起后不保留图标栏，画布吃掉释放出来的宽度。侧栏实现为**「占位 gap + 绝对定位面板」**（2026-11-27 定稿，参考 shadcn Peek & Pin 与 OpenCode）：gap 是空 div，宽度 0/220 之间过渡，**画布的左右移动只由它驱动**；面板永远绝对定位、靠 `translateX(-100%) ↔ 0` 进出（合成器动画，列表不重绘）。**收起状态下鼠标停在折叠按钮上会临时弹出抽屉**：只把 transform 归 0，gap 仍是 0，画布一帧都不动；**抽屉开着时点折叠按钮 = 停靠**：面板原地不动、gap 从 0 长到 220，画布从面板下方平滑右移，结束时两者重合。指针离开按钮与面板约 180ms 后自动收回（中间隔着标题栏，不能立刻收）。面板里选完文件夹或标签会直接收起；点按钮仍是原本的持久展开/收起。面板用同一个侧栏实例，不复制——折叠状态与滚动位置不会丢；描边与投影只在浮层态出现（上边 + 右边各 1px `--border`，上边接着画布顶边那条线），这两条线用面板内绝对定位的 1px 线画、不占布局（用 `border` 会挤掉面板内侧 1px，停靠成展开时内容会抖一下）。
- **侧栏只显示用户勾选过的文件夹**：侧栏底部有「选择文件夹」入口，点开扫描服务器上的完整文件夹清单（`folders:scan` → `refreshFolders`），勾选后才显示并参与同步；未勾选的不同步、不占侧栏，本地已下载的邮件保留。收件箱强制显示；新发现的系统文件夹默认勾选，新发现的自建文件夹默认不勾选（避免公司邮箱一连接就拉进一堆没用的目录）。升级前的历史文件夹全部保持勾选，不会突然消失。子项全部未勾选时，父容器分组也一起隐藏，不能出现「其他文件夹 > 其他文件夹」这种重复项（先按完整清单计算层级，再按勾选过滤）。
- 侧栏文件夹列表**占满底部同步/设置区以上的全部高度**（`flex-1 min-h-0`，超出时才在列表内部滚动）。不要用 `max-height: 45vh` 之类的固定上限——公司邮箱的个人文件夹很多，窗口明明还有空间时列表就被截断，用户只能盲目内滚找文件夹。
- 第二栏选中项与第三栏联动；阅读器没有关闭按钮，第三栏始终存在（双栏模式未实现）。
- 不设全局顶栏，搜索框以组合胶囊的形式**常驻标题栏中间**（没有搜索图标入口，也没有独立的搜索对话框）：左侧是范围下拉，右侧是输入框，输入即把当前列表切换成搜索结果。

### 4.3 同步状态面板

侧栏底部同步状态行**保留「点击 = 手动同步」**，行右侧另有一个 20px 按钮（内部 12px `Pulse` 图标）打开面板；侧栏收起时整行随侧栏一起隐藏（手动同步走 `Ctrl+R`，要看同步详情需先展开侧栏）。

面板是**只读**的，打开它不能发起任何 IMAP 请求，也不能暂停/恢复定时器：

- 顶部：账户总数与「正在同步」摘要；最后一次同步时间、轮询 / 对账倒计时在每个账户卡片里。
- 账户卡：邮箱、服务器与加密方式、连接状态、错误原文、队列任务数、待推送已读、缺正文数；`error`/`disconnected` 时出现「重连」。
- 文件夹表：本地封数、最近一次看到的服务端封数、未读、回溯进度、当前忙碌状态；只列启用文件夹。**表格自身限高滚动、表头吸顶**（2026-11-27 用户要求）：超过 11 行就在表格内部滚，**容器高度必须是「表头 29px + 整数行 × 27px」**（2026-11-27 用户明确要求：初始状态不能露出半行），当前固定显示 11 行；表头用吸顶的 `bg-background`，不能靠拉长整个面板来容纳文件夹；账户区本身最高占 66%，两者不会互相裁切。
- 最近事件：渲染层保留本次会话最近 200 条同步事件，按时间倒序展示最近 80 条。
- 底部：日志路径与「打开目录」；自动刷新 1s（仅在面板打开时轮询）。
- 操作：立即同步、复制诊断、重连、打开日志目录。面板不提供修改同步参数或下载范围的入口。
- 状态色：`primary`（正在连接/下载）、`success`（已同步）、`muted-foreground`（未连接/空闲）、`destructive`（错误）；状态必须带文字，不能只靠颜色。

## 5. 功能需求

### FR-01 账户接入（P0）

**描述**：用户手动填写邮箱地址、IMAP 主机、端口、加密方式、用户名、密码/授权码，点击"测试连接"，通过后保存。表单只有「自定义」一种形态，不做服务商预设。

> **只依赖收件服务器（IMAP）**：账户表单不出现 SMTP 字段，测试连接与同步也不探测、不校验发件服务器。发件服务器不通、端口被防火墙挡住、甚至根本没开，都必须能正常添加账户并收到信。

**规则**：
1. 初始端口 993（TLS）；加密方式五选一：TLS（993，校验证书）/ STARTTLS（143，要求升级并校验证书）/ TLS · 忽略证书（993，仍然加密，跳过证书校验，给公司自签名证书用）/ STARTTLS · 忽略证书（143，要求升级，但跳过证书校验）/ 不加密。**切换加密方式不会自动改端口**，选 STARTTLS 要把端口手动改成 143。**「不加密」不等于跳过证书校验**，公司内网自签名证书应当选「TLS · 忽略证书」或「STARTTLS · 忽略证书」，否则用户会被「测试失败、保存后却能收信」误导。
2. 密码默认用 Electron `safeStorage`（Windows DPAPI）加密后单独存储；加密不可用的极少数环境下降级为明文，并在 `credential.scheme` 标成 `plain`，方便识别需要重新登录的账户。
3. **不做服务商预设**：本应用只服务公司自建服务器，表单直接呈现 IMAP 主机/端口/加密方式，不用选 QQ/163/Gmail/Outlook。默认端口 993、默认加密 TLS，主机留空由用户填。
4. 测试连接动作：TCP 连接 → TLS / STARTTLS 握手 → LOGIN → 列出文件夹 → 断开。超时口径：连接与问候各 12s、socket 30s（`src/main/net/probe.ts` 的 `connectionTimeout` / `greetingTimeout` / `socketTimeout`）。**测试连接与真实同步必须共用同一套连接参数**（`src/main/sync/connection.ts` 的 `buildImapOptions`）：早先测试固定校验证书、同步在「不加密」下不校验，导致测试报证书错误、保存后却能正常收信（用户 2026-11-23 实测）。错误文案必须给下一步动作（自签名 → 选「TLS · 忽略证书」/「STARTTLS · 忽略证书」，或导入根证书；超时 → 检查端口与内网/VPN；STARTTLS 不可用 → 改 TLS 993），且完整展示、不截断。
5. 账户只保存 IMAP 相关配置，不保存 SMTP 主机/端口/凭据：本项目只收信，发件服务器不可达不构成任何失败（企业内网常见只有 993 通、25/465/587 被封的情况）。
6. 多账户并存：标题栏左段的账户入口（☰）点开是账户列表（当前项打勾，显示名称 + 地址），选中即切换；每行右侧有编辑与删除，列表底部「添加账户…」直接打开新增表单。切换账户时文件夹树、列表、阅读器、未读数一起切到该账户，旧账户的选中邮件清空。新增账户保存后立即为该账户启动同步，无需重启。
7. **编辑 / 删除账户**：点行内铅笔复用同一张表单（标题变成「编辑账户」，字段预填、密码留空表示不修改）；删除需要确认，主进程会一并清掉该账户的本地邮件与附件缓存。保存走 `accounts.update`，只有邮箱/主机/端口/加密方式/用户名/密码这类连接参数变化时才重启该账户的同步；仅改显示名不会重连。**账户弹窗只保留新增/编辑表单这一档**，列表、切换、编辑、删除都在 ☰ 浮层里，不再有「列表 ↔ 表单」的高度切换。
8. **邮箱地址 = 账户身份，用户名 = IMAP `LOGIN` 的账号**：用户名留空时保存为邮箱地址；部分公司服务器的登录名不是邮箱（`DOMAIN\user`、`sAMAccountName`），这时填用户名。**编辑账户时，若用户名仍等于旧邮箱（或为空），改邮箱会同步改用户名**；用户手填过的登录名原样保留，避免「改完邮箱还拿旧账号去登录」认证失败。

**验收标准**：
- [ ] 网络可达时，输入错误密码能尽快显示可读错误（连接 / 问候各 12s、socket 30s 超时；区分：网络不可达 / 证书错误 / 认证失败 / 端口与加密方式不匹配 / STARTTLS 不可用）。
- [ ] 测试连接的结果与保存后的实际同步一致：测试通过则保存后能收信；测试因证书失败时，引导用户改用「TLS · 忽略证书」或「STARTTLS · 忽略证书」后测试通过。
- [ ] 163/126 邮箱在未发送 IMAP ID 时不应失败（内核自动发送 ID）。
- [ ] 保存后无需重启即可在文件夹树中出现该账户。
- [ ] 发件服务器（SMTP 25/465/587）完全不可达时，添加账户、测试连接、收信全部正常，不出现超时或报错。
- [ ] 两个账户可在标题栏 ☰ 菜单里切换，切换后文件夹与邮件来自对应账户，不串数据。

### FR-02 文件夹（P0）

**描述**：连接成功后拉取文件夹列表，展示为树。系统文件夹置顶并映射到固定角色。

**规则**：
1. 文件夹名需处理 **modified UTF-7** 解码（中文文件夹名常见）。
2. 角色识别优先级：`\\Inbox` → inbox；`\\Sent` → sent；`\\Trash` → trash；`\\Junk` → junk；其余为普通文件夹（`\\Archive` 不识别，按普通文件夹处理）。
3. **未读数只以本地库为准**（`SELECT COUNT(*) WHERE is_read = 0 GROUP BY folder_id`），侧栏角标（默认显示未读数，可在设置里切换成显示文件夹的邮件总数）；列表本身不再显示「N 封」标题行（列表已改成文档页签结构，只有文件夹页签显示文件夹名）。不要用 IMAP `STATUS (UNSEEN)`（服务器未读在与本地已读不同步时会偏大），也不要用「当前已加载的那一页」去数（那是 126 与 255 打架的原因）。标为已读时先乐观减一，IPC 返回后重新拉一次真实值；切换文件夹不得残留上一箱的数字（不闪旧值）。
4. 只读文件夹（`\\Noselect`，即容器目录）与普通文件夹**同款样式**，但不参与选中：整行只负责展开/收起，右侧给 chevron（展开 `ChevronDown` / 收起 `ChevronRight`），点整行或箭头都切换；不显示未读数。子文件夹每级缩进 14px、可正常选中，层级按路径段数递归。QQ 邮箱的 `其他文件夹/Steam`、`其他文件夹/QQ邮件订阅` 即此结构。侧栏收起时整个侧栏隐藏（gap 0 + 面板移出），不保留 50px 图标栏，所有文件夹一起不可见。
5. 当前选中项若指向容器（服务器改了层级等），自动落回收件箱，不出现「列表空且无选中」的死状态。
6. **不做同名合并**：服务器上的普通目录与系统箱子可能只是名字像、实际是两个不同邮箱（UIDVALIDITY 不同），一律各自显示，不做按名字的过滤。为避免混淆，系统草稿箱的本地化标签是「草稿箱」，服务器自建的普通「草稿」目录原样保留。QQ 邮箱同时返回 `Drafts`（role=drafts，显示「草稿箱」）与 `草稿`（role=null，显示「草稿」）。
7. **`\Archive` 不提升为系统「归档」**：服务器上的「存档」等目录按普通文件夹处理，留在自建目录树里，避免同一个邮箱同时出现在系统区和自定义区。
8. **自建目录归组**：所有顶层自建文件夹（含服务器没给父容器的）统一收进「其他文件夹」分组，缩进一级显示。服务器给了 `\Noselect` 容器就用它当分组节点，没给就生成一个不可选中的虚拟分组。分组可折叠；侧栏收起时整块一起隐藏。**默认（系统）文件夹与自建文件夹之间画一道 1px 分隔线**（2026-11-27 用户要求，挂在第一个自建项上方、左右各内缩 8px，颜色取 `--border`；没有自建文件夹时不画）。

**验收标准**：
- [ ] 中文命名的文件夹显示正确，不出现 `&UXZO1mWHTvZZOQ-` 这类编码串。
- [ ] 服务器上的每个可选文件夹都在侧栏出现且只出现一次（QQ 的 `Drafts` 显示为「草稿箱」、普通目录「草稿」独立显示，两者可分别打开且邮件不同）。
- [ ] 顶层自建文件夹（QQ 的「草稿」「存档」「QQ邮件订阅」）全部出现在「其他文件夹」下，不与系统文件夹混排。
- [ ] 未读徽标与实际未读数一致（±0）。
- [ ] 重复点击当前文件夹不会重新加载，列表不出现空骨架或空占位。

### FR-03 邮件列表（P0）

**描述**：按时间倒序展示当前文件夹邮件摘要。

**规则**：
1. **标准视图行结构**：行首 28px 彩色圆形头像（首字母，见 6.3 第 7 条）。**标准默认只展示发件人与主题两行（行高 60px）；设置里开启「标准视图显示三行」后变成三行、行高 72px**——第一行 未读蓝点（6px）+ 发件人（13px/500，无则显示邮箱）+ 右侧时间；第二行 主题（14px，未读 600、`text-foreground` / 已读 400、`text-ink-read`，单行省略）+ 右侧附件。开启三行后第三行是摘要（13px、未读 `text-muted-foreground` / 已读 `text-ink-faint`、单行省略）；两行模式把附件放在主题行右侧。时间格式：当天 `HH:mm`，本年 `M月d日 HH:mm`，跨年 `yyyy/M/d HH:mm`（标准视图默认在日期后带小时分钟，可在设置里关掉「标准视图显示时分」只留日期；当天仍只显示 `HH:mm`。搜索结果与普通列表共用同一套格式，不做特殊短格式）。
1.1 **紧凑行结构**（行高 26px，表格式单行，1:1 对齐 Foxmail）：不显示头像、摘要与三行堆叠，改为一行固定列——状态列（26px = 行首留白 8px + 18px 槽位，圆点居列正中）→ 附件列（18px，回形针，**与状态列各自独立**，不是共用一个槽）→ 发件人（默认 140px，单行省略，未读 500 / 已读 400；选中行的未读也回落 400）→ 主题（自适应剩余宽度，单行省略，未读 600 / 已读 400）→ 日期（默认 72px 右对齐 `tabular-nums`，始终带时分）→ 大小（默认 52px 右对齐，`KB` / `MB` 单位，空值留白）→（紧凑视图没有星标列；置顶邮件不参与大小分组，统一排在最前，见 1.4）。状态列**每行都画一个 9px 圆点**（列头图例同尺寸）（仅紧凑模式）：未读为 `--primary` 蓝点、已读为中性灰点 `--dot-read`（选中行也保持同一套颜色）；点圆点直接切换已读/未读，`stopPropagation` 不选中该行。每行底部有 1px `--row-line` 横向分隔线，用伪元素画且左右铺满到卡片左缘与列表/阅读器分隔线（2026-11-27 用户要求延长，与表头、组头的线对齐；选中行也保留，选中时靠底色区分而不是去掉线）；行内不设 `gap`，靠单元格 padding 对齐列头。
1.2 **紧凑日期列与列头**（Foxmail 口径）：列表顶部固定一行高 28px 的列头「状态 / 回形针 / 发件人 / 主题 / 日期 / 大小」，每列右侧有 1px 竖向分隔线（用 `.col-sep` 伪元素画，**上下贯通、与列头的横线相交**，2026-11-27 用户要求），列宽与数据行完全一致、不参与滚动，空列表不显示；**列头只取决于「有没有数据」，不能受 loading 控制**——刷新已有数据时若卸载列头，内容会整体上移 28px，表现成闪烁。**发件人 / 日期 / 大小三列可拖动分隔线调宽**：分隔线始终跟着鼠标走，把手都落在「可动的那条边」上——发件人列左边界挨着固定的 18px 回形针列、动不了，所以它的把手在**发件人与主题之间**那条线上（向右拖发件人变宽）；日期、大小的把手在各自**列名左侧**的线上（向左拖变宽）。三处命中区都是 6px，拖动时高亮为主色，鼠标离开把手后仍可继续拖（监听挂在 window 上）；宽度存 `localStorage["maildesk.compactCols"]`，双击分隔线恢复该列默认值；最小宽 56 / 72 / 48px（日期低于 72px「11-21 23:20」会折行，大小列同理，两列都设 `whitespace-nowrap` 兜底），最大宽度受列表宽度约束——拖到主题列只剩 96px 就停，列表整体被拖窄时自动收窄这三列。滚动条是浮层（见 6.3 第 8 条），不再占内容宽度，列头因此不需要为它让位；代码里仍保留 `offsetWidth - clientWidth` 的动态让位（浮层化后恒为 0），作为将来换回原生滚动条时的兜底。日期列当天显示「凌晨0:34 / 上午9:06 / 中午12:10 / 下午1:20 / 晚上8:15」，同一年显示「11-21 23:20」，跨年显示「2025-04-30」；**日期列被拖宽到放得下时自动带周几**（`11-19 (周四) 13:28`、跨年 `2025-04-30 (周三)`），放不下就退回原短格式——是否放得下用 canvas 按 12.5px 实际字体量「11-19 (周四) 13:28」的宽度，不要写死阈值；**日期与大小两列的字号（12.5px）和明度与主题列完全一致**（已读 `text-ink-read`、未读 `text-foreground`，选中行不变白，仍按已读/未读取深浅），不做第二档弱化；标准视图仍用原来的短格式（当天 `HH:mm`、本年 `M月d日`、跨年 `yyyy/M/d`）。选中行整行铺满（左边缘到列表右边）填充浅蓝 `--row-selected`、文字保持正常的已读/未读深浅（2026-11-24 用户指定），行为与标准视图一致。列头的「日期」「大小」都是按钮并按体积/时间分组：点「日期」按时间分组、点「大小」改成按体积分组（超大 ≥5M / 很大 1–5M / 大 500K–1M / 中 100K–500K / 小 25K–100K / 较小 5K–25K / 很小 <5K），再点当前列头在降序 / 升序之间切换（日期升序即从旧到新，大小升序即从 很小 到 超大，组内顺序同时反向）。**只有当前分组的列显示方向箭头**（降序 `ChevronDown`、升序 `ChevronUp`），另一列不画箭头；分组列不靠字体颜色标记，文字颜色与未分组时一致。组头条同样可折叠、可吸顶。

6. 支持按发件人聚合（P2）。
7. 空文件夹显示 32px 图标 + 一句文案，不显示空白。
8. **邮件行右键菜单**（与 Foxmail 对齐）：右键任意邮件行只**高亮该行并切换阅读器**，不标已读、不自动滚动；菜单项为「标为已读 / 标为未读（U）→ 置顶 / 取消置顶（S）→ 标为垃圾邮件 → 移动到…（子菜单）→ 复原（仅垃圾箱）→ 删除（Delete）」。**「标为垃圾邮件」只在当前文件夹本身就是垃圾邮件时隐藏**（垃圾箱里仍显示）。垃圾箱里额外有「复原」：把邮件通过 messages:move 移回收件箱（role === "inbox"），保留原 id、正文缓存与已读态；本项目不记录「原文件夹」，复原一律回收件箱，UI 不要暗示能回到原子文件夹；找不到收件箱时提示「复原失败 · 找不到收件箱」。移动到子菜单复用侧栏命名（排除 `\\Noselect` 容器与当前文件夹，并在**默认（系统）文件夹与自建文件夹之间画一条分隔线**，2026-11-27 用户要求；阅读器工具栏的「移动到」下拉用同一份候选与同一条分隔线；两个菜单的高度都跟随内容、不内滚，2026-11-27 用户要求）。
9. **多选**：`Ctrl/⌘ + 点击`在选中集合中增减一行，`Shift + 点击`从当前活动行到点击行整段选中（不标已读），普通点击清空多选回到单行；`Ctrl+A` 无条件生效：选中**整个当前文件夹**（搜索面板里则选中当前结果集），无需先选中一封；同时阻止浏览器选中页面文本。多选与全选都**不标已读**（避免批量选中把一堆未读变成已读），也不触发「停留 1.5 秒自动已读」。`selectedId` 仍是其中的活动行，决定阅读器内容与滚动定位；行底色由 `selectedIds` 集合决定（集合为空时才回落到 `selectedId`），不要只比 `selectedId`——否则 `Ctrl+A` 集合已全选，界面却只亮一行，看起来像没反应。多选态下 `Delete` / `Backspace` 批量删除（垃圾箱内为永久删除）并收起多选，`J/K` 上下移动会收敛回单行。
10. **滚动位置只在换文件夹 / 换搜索条件时归零**：删一封（或一批）邮件后，列表必须停在原处，不能跳回顶部，也不能整块刷新闪烁。因此：回顶部的 effect 只依赖 `folderId` 与 `resetKey`（搜索条件，`query|scope`），**不能依赖 `messages[0]?.id`**（删掉首行也会变，等于每删一封就归零）；删除/移动成功后**不再整箱重取**——本地 filter 就是终态，只有部分失败（IPC 只回计数，界面猜不出是哪几封）才回库兜底；主进程的本地变更回执（`messages` 事件且 `added === 0`）只刷计数、不重拉列表，避免一次删除触发两个加载周期；刷新已有数据时不要切骨架屏——骨架会清空滚动容器的内容高度，`scrollTop` 会被浏览器夹到 0，只有「没有任何邮件」时才显示骨架（`loading && messages.length === 0`）。

**验收标准**：
- [ ] 10,000 封邮件滚动无明显掉帧（DevTools Performance ≥ 55 fps）。
- [ ] 切换文件夹时列表不出现内容闪烁（保留骨架屏 ≤ 200 ms）。
- [ ] 时间格式化符合上述规则，跨天/跨年边界正确。

### FR-04 阅读器（P0）

**描述**：渲染选中邮件的头部信息、正文与附件。

**规则**：
1. 正文区任意位置右键 = 和列表行完全相同的邮件菜单（标为已读/未读、全部标为已读、置顶、标为垃圾邮件、移动到…、复原、删除）；HTML 正文在 iframe 里，右键由同源监听换算坐标后转发给正文区，不额外做一套原生菜单。头部：主题（大字号）→ 发件人区（左侧头像与右侧两行信息**整体垂直居中**；第一行发件人姓名 + 操作图标组（置顶、标记未读、保存全部附件、「移动到」下拉、删除），第二行邮箱地址 + 完整时间）→ 收件人/抄送（折叠态只有一行摘要：≤3 人时列全名；人多时「发给 甲、乙 等 N 人」，有抄送再追加「· 抄送 M 人」，整行 `truncate` 不换行。点开是浅色面板：发件人一行 +「收件人 N」「抄送 M」两组联系人。**每行只显示一位联系人**：姓名与地址在同一行，姓名近黑且保持完整不省略，地址用去掉尖括号存储、展示时包成 `&lt;address&gt;`、次要色（超长时只在括号内省略，`title` 给完整 `姓名 <地址>`）；显示名整段同色，不要按「/」拆段加粗或改色，无姓名时只显示地址；**姓名必须从 To/Cc 原始头解析**（同步时随 `headers: ["to","cc"]` 取回，RFC2047 解码），因为 QQ 等服务器的 ENVELOPE 会把 personal name 填成地址本地部分，单组最高 260px 内部滚动。公司邮件常见几十个收件人，**不能**再用「、」把全部地址拼成一堵墙）→ 标签与附件 chip → 正文。**不再有独立的 52px 工具条**，图标与发件人同行后正文整段上移，`article` 顶部只留 20px（`pt-5`）。图标组**最右侧**是「该发件人的全部邮件」抽屉按钮：点开右侧 320px 抽屉，头部显示发件人头像、姓名与邮箱地址（不再写「该发件人的邮件」这类说明文案）；按发件地址跨文件夹列出这个人的全部邮件（未读点、主题、完整时间，不显示正文摘要，当前这封高亮），点击任意一条即切到对应文件夹并选中打开。**没有关闭按钮**：`Esc`、点抽屉外的空白处（透明遮罩，不加暗色）或换成其他发件人时收起（同一发件人内切换保持展开）。时间格式 `yyyy年M月d日 周X HH:mm`（周三这类「周X」写法，不用「星期三」）。
2. 正文渲染优先级：`text/html` → 沙箱渲染；无 HTML 则 `text/plain` → **画布直排、不套卡片**，按空行分段、块内保留换行与缩进（`whitespace-pre-wrap`），行宽 `max-w-[76ch]` 左对齐、不做版心居中，长 URL 与长单词 `break-words`；整块以 `>` 开头的引用用左侧 2px 竖线 + 12px 缩进、次要文字色，同样不画卡片。
3. HTML 安全：
   - 使用 DOMPurify 清洗，移除 `script`、`iframe`、`object`、`form`、事件属性、`javascript:` 协议。
   - 渲染于**禁用 Node 集成的 iframe `sandbox="allow-same-origin"`**（不带 `allow-scripts`，选型见 7.3；`<webview>` 已弃用）。
   - 基础样式只做排版兜底：`margin` / `padding` 归零、`font-size`（默认 14px，可在设置里 13–16 调）+ `line-height: 1.7`、链接色 `#1a5fd0`、`blockquote` 左侧 2px 竖线、`pre` 保留换行；**不注入** 图片 `max-width`、表格 `max-width`、单元格 `overflow-wrap` 这类压宽规则——源邮件的定宽版式、图片尺寸原样保留，超宽由阅读区横滚承担（2026-11-28 与实现对齐）。
   - 保留邮件自带的内容区背景色（表格 / 单元格 / 卡片的 `bgcolor`、`background`、`background-color`）与 `<style>` 块（iframe 沙箱隔离，只作用于邮件文档）；去掉它们会丢掉横幅、分隔线与表格宽度。**页面级背景也原样保留**：`html` / `body` 的 `bgcolor` / `background` / `style` 合并进最终文档，没有背景的邮件才是透明的、落在 `bg-card` 画布上（2026-11-28 与实现对齐）。**`<head>` 里的 `<style>` 必须保留**：DOMPurify 默认只返回 body 内容，`<head>` 会被整块丢掉，字体族、字号、行高、媒体查询与 `body` 背景随之失效（2026-11-24 实测：457 封里 189 封把样式写在 `head`，只有 33 封写在 body 内）。清洗必须带 `WHOLE_DOCUMENT`，再把 `head` 的 `<style>`（含 `media` 属性）搬进最终文档的 `head`，顺序在应用基线样式之后，让邮件自己的规则优先生效；`<html>` / `<body>` 上的 `style`、`bgcolor`、`background`、`class`、`dir`、`lang` 也要合并到最终文档，否则页面底色与按 `class` 选择器写的样式全部失效。**但 `html` / `body` 的高度必须归零**：营销邮件常写 `<html style="height:100% !important">` / `body { height:100% !important }`，内联 + `!important` 连基线样式都盖得过，body 被钉成 iframe 视口高度，高度测量与 `documentElement.scrollHeight` 只剩首屏、正文被 `overflow:hidden` 裁掉（2026-11-27 实测一封 Microsoft Rewards 只显示了顶部横幅）。合并属性时剥掉 `height` / `min-height` / `max-height`，并在邮件样式**之后**再追加一段 `html, body { height:auto !important; min-height:0 !important; max-height:none !important }` 守卫。
   - **不做统一容器、不改定宽**：不把页面级定宽改成百分比，也不重写 `<style>` 里的 px 宽度；iframe 宽度按 `max(阅读区宽度, 邮件声明宽度, 实测内容宽度)` 铺开，超出阅读区的部分交给阅读区横向滚动条（旧版「清页面底色 + 定宽改 100%」方案已删除，2026-11-28 与实现对齐）。
   - **文本优先渲染（不做整页缩放、不套「印刷品」白纸卡片）**：iframe 不 `zoom`、不缩放，直接落在阅读画布上；`article` 左右 24px，列表模式下正文容器最宽 900px，双击进入邮件页签后取消 900px 上限（2026-11-27 用户要求）；固定字色 `#242424`、链接 `#1a5fd0`；字体 / 字号 / 字重跟随源邮件，只对直接承载文字的节点做对比度兜底（与有效背景 < 3:1 时改成深色或浅色，遇到 `background-image` 跳过）。没有 `data-maildesk-table` 之类的 Excel 特判（未实现）。
   - **不放任邮件自造的小滚动框**：营销/通知邮件常用「固定高度 + `overflow:auto/scroll/hidden`」做内嵌小窗，阅读区明明有空间却只能在 250px 里滚（用户 2026-11-24 要求）。渲染时统一放开：先按内联 `style` 把 `height` / `max-height` 改成 `auto` / `none`（高度 < 24px 的跳过，那是 preheader 隐藏块的惯用写法），正文加载后再按计算样式兜一次（覆盖类选择器与带 `!important` 的规则），条件是「`overflow-y` 为 auto/scroll/hidden、元素高度 ≥ 24px、且 `scrollHeight` 超出 `clientHeight`」。
- **滚动条只属于阅读区**（用户 2026-11-24 要求）：iframe 带 `scrolling="no"`，正文文档 `html, body { overflow: hidden }`，邮件内部不出现滚动条；宽度不压缩（见上），内容比阅读区宽时把 iframe 撑到内容宽度，横向滚动条由阅读区的原生滚动条承担（`.scrollbar-native`，2026-11-25 起），绝不裁剪内容。
- **高度自适应**：iframe 高度取内容实际高度（body 盒高与文档滚动高的较大值），图片加载、窗口缩放时用 `ResizeObserver` 重算，正文底部不留大片空白。
   - **失效图片与追踪像素**：加载失败的 `<img>` 不允许显示浏览器默认的碎图图标。声明尺寸 ≤ 2px 的（0×0 / 1×1 追踪像素，常见实现是返回 1 字节的“图片”）直接 `display:none` 不占位；有正常声明尺寸的失败图**整体替换成同尺寸的占位 `<div>`**（浅灰底）并保留原尺寸——只删 `src` 不够，空 `<img>` 浏览器照样会画碎图图标。QQ/Apple 这类客户端要么走图片代理，要么直接隐藏失败图，不会把 Chrome 的破图图标暴露给用户。
3.5 **正文版式（固定原版式）**：不再提供「正文适配方式」设置项。页面底色、定宽、字体、图片尺寸全按源邮件，**不缩放也不压宽**，超宽内容（定宽版式、宽表格、大图）由阅读区横向滚动条接手，绝不裁剪。实现上先按阅读区宽度排一遍量出 `scrollWidth`，再用「元素上写死的最大宽度（`width` 属性或内联 px，≥240px）」推定设计宽度，取 `width = max(pane, design, laidOut)` 铺开 iframe，高度按该宽度实测；不含 `transform: scale`，右键坐标 1:1 换算。旧的重排（`reflow`）与整封等比缩放（`zoom`）均已删除，不要恢复对应设置或渲染分支。
4. 远程图片：默认**放行**（`remoteImages: true`）；设置为拦截时替换为占位块，顶部提示"已拦截 N 张远程图片 [显示图片]"，点击后本次会话放行。**拦截态必须在邮件文档里注入 CSP**（`default-src 'none'; img-src data:; style-src 'unsafe-inline'; font-src data:; script-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`）——只替换 `<img>` 堵不住 `<style>` 里的 `@import`、`background-image: url()` 与 `@font-face`，营销邮件仍能靠这些通道回传「谁在什么时候打开了信」。放行态只放开 `img-src` / `font-src`，脚本与外部样式表永远不放。`cid:` 内嵌图片在同步时随正文一起取回并转成 data URL 嵌入（单张 ≤10MB 编码尺寸、整封 ≤16MB 解码合计），正文里的截图直接可见；超过上限、取不到或老数据才回退透明占位 + `alt="内嵌图片"`，不要显示碎图标。**上限必须能覆盖「整封 2MB 以上的纯图片宣传邮件」**：`image.size` 是 base64 后的尺寸，2MB 的图对应约 1.5MB 原图，旧上限会让这类邮件整封空白（2026-11-26 用户实测）。
5. 附件判定：**正文内嵌图不算附件**——`multipart/related` 里带 `Content-ID` 的图片、或 `Content-Disposition: inline` 的图片，既不挂回形针也不生成附件 chip（营销邮件把配图写进正文的情况很常见）；只有真正的附加文件才计入「有附件」。正文用 `cid:` 引用的内嵌图属于正文的一部分，同步时一并取回（不算附件、不挂回形针）。
6. 附件交互：**双击附件 chip = 打开**（图片弹内联预览层，其他类型直接用系统默认程序打开缓存文件），**单击不做任何事**（2026-11-27 用户要求，避免想右键/选中时误触打开）；**右键 chip 出菜单：打开 / 保存… / 保存全部…**。下载时 chip 上显示百分比（主进程按 120ms 节流推 `attachments:progress`，进度拿不到总大小时仍显示 spinner）。`attachment.part` 在正文解析时记下 BODYSTRUCTURE 的 part 号，保存/预览/打开直接按它取那一段，省掉每次一次的 `fetchOne` 结构查询（老数据没有 part 时自动回退）。**固定渲染在发件人信息下方、正文之上**（写在 `Article` 头部的 `Chips` 区），长正文时不必滚到底也能看到；展示文件名、大小、类型图标；打开 = 图片走内联预览、其他类型走系统默认程序（不弹保存对话框）；图片预览层内可再保存；**预览层的关闭条件必须覆盖「加载中 / 加载失败 / 已加载」三种状态**——只清 `preview` 会把错误提示永久钉在屏幕上（实测点开非图片附件后整窗卡死），所以统一走 `closePreview()`（同时清 `preview`/`previewError`/`previewBusy`），Esc 与点击浮层空白处同样生效；是否走预览只看 MIME 前缀 `image/` 或图片扩展名，**不能**用列表图标分类 `Attachment.type`（压缩包是 `application/octet-stream`，会被服务端拒绝）；保存状态在 chip 上以 spinner/对勾反馈，用户取消视为无操作，失败标红。工具条「保存全部附件」一次选目录，同名文件自动追加序号不覆盖。附件 chip 与标签 chip **同一行**（`flex-wrap`，标签在前、附件在后）：标签是 20px 胶囊；附件是 **36px 高的文件卡片**（2026-11-27 美化，取代原来的 20px 灰胶囊）——白底 + 1px `--border`、10px 圆角，左侧 24×24 主色淡底图标块，右侧两行文字（上行文件名 12px、下行大小 10.5px `tabular-nums`）；hover 时边框转主色、底色转 `--accent`；下载中图标块显示百分比、卡片底部 2px 主色进度条，禁用双击；保存成功图标块与下行转 `--success`，失败转 `--destructive`。附件多时换行，超过 3 个折叠为同高的虚线描边「+N 个附件」按钮。
7. 编码：解析失败回退 `iconv-lite`（GBK/GB2312/GB18030 常见于国内老邮件），仍失败则展示"无法解码"并允许查看原始源码。
8. 移动与删除（工具栏，按钮文案随所在文件夹变化）：
   - 「移动到」下拉列出侧栏里所有可选中文件夹（复用侧栏命名，排除 `\Noselect` 容器与当前文件夹）；选中后立即调用 `messages:move`，本地行随服务器 MOVE 改到目标文件夹并保留 id/正文缓存/已读态。
   - 「删除」在普通文件夹是**移到垃圾箱**（`role === "trash"` 的文件夹）；已在垃圾箱里时变成**永久删除**（EXPUNGE），按钮 title 相应变为「永久删除 (Delete)」，不弹二次确认，靠垃圾箱本身兜底。
   - 两个操作成功后都从当前列表移除该行、清空阅读器、刷新文件夹计数与未读数。
9. 操作失败反馈：移动/删除是「服务器先行」——服务器不可达或被拒绝时本地不变，**不能静默吞错**。失败时在窗口底部居中弹出一次性提示条（~Notice~：红色警示图标 + 一句话原因，3.5 s 自动消失，不打断阅读）。错误串按关键词归一成人话：含 ~network~ →「网络未连接，请稍后重试」，含 ~auth~ →「账户授权失效，请重新填写密码」，含 ~not-found~ →「目标文件夹已不存在」，其余取最后一个 ~Error: ~ 之后的内容。~result.failed > 0~ 时也按同样方式提示。
10. **链接与引用**：页内 `#` 锚点交给 iframe 自己滚；`http(s)`、协议相对 `//`、`mailto:`、`tel:` 交给系统打开（主进程白名单同步放开）；其余（相对路径、`file:`、`javascript:`）一律 `preventDefault`，邮件不能把应用导航走。长线程的引用历史按 `blockquote` / `.gmail_quote` / `#divRplyFwdMsg` / `.yahoo_quoted` 识别（只取最外层，高度 > 260px 或文字 > 500 字），折叠成「显示引用内容（N 字）」横条，点击展开/收起——Gmail、Apple Mail、Outlook 都是这个行为。

**验收标准**：

### FR-05 同步引擎（P0）

**描述**：后台持续把 IMAP 邮件增量落库，并通过事件通知 UI。

**规则**：
1. **只同步用户勾选的文件夹**：`syncAll` / 历史回溯 / 对账 / 正文补齐都只处理 `folder.enabled = 1` 的文件夹；未勾选的文件夹不建游标、不拉历史、不下载正文，托盘未读数也只统计启用文件夹。`refreshFolders` 仍然扫描服务器全部文件夹并写库（否则弹窗里看不到它们），但不覆盖用户已有的 `enabled` 选择。
2. **连接账户后无条件全量下载（已勾选文件夹），并且正文一起落库**：不做「全部 / 最近 N 封 / 不自动」这类策略；首屏先取收件箱最近 200 封（`pageSize`）/ 其他启用文件夹各 200 封让界面可用，其余历史由后台回溯循环一路补到服务端最后一封；回溯每批 500 个 UID（`BACKFILL_BATCH`），先取 `envelope/flags/internalDate/size/BODYSTRUCTURE`，随后按结构里的正文 part 号批量取回 `text/plain`、`text/html` 与内嵌截图（带 Content-ID 的 image part，单张 ≤10MB 编码尺寸、整封 ≤16MB 解码合计；
   - 回溯游标 `folder.backfill_uid` 持久化（下一批的上界），**不能**用 `MIN(uid) - 1` 推算——服务端 UID 有空洞（删除过邮件），空批次会让 `MIN` 原地不动而死循环；每批无论命中与否都必须把游标推进到 `from - 1`，`< 1` 表示翻到底，`null` 表示还没开始。
   - 进度通过 `SyncEvent { type: "backfill", folder, done, total, finished }` 推给 UI，侧栏同步文案显示"补全历史 N / M"。
   - **首次连接必须可见地「在动」**：连接阶段显示「正在连接服务器…（Ns）」，下载阶段显示「正在下载 收件箱 50 / 200」，正文预下载显示「正在下载正文 N / M」，历史回溯显示「补全历史 N / M」。列表还没有邮件时，空态换成「首次同步进行中」+ 当前进度，绝不能显示「这个文件夹还是空的」。`SyncStatus` 里带 `startedAt` / `progress` / `bodies` 快照，界面晚于同步启动（重载、切账户）也能立刻恢复进度。
3. 增量：记录 `last_synced_uid`，每次 `UID FETCH (last_synced_uid+1):* (ENVELOPE FLAGS INTERNALDATE RFC822.SIZE BODYSTRUCTURE To Cc)`。
4. 实时：对 INBOX 建立 IDLE 连接，收到 `EXISTS` 后触发增量拉取，**不重新登录**。
5. `UIDVALIDITY` 变化 → 清空该文件夹本地数据 → 全量重拉（必须有明确日志）。
6. 断线：指数退避重连（2s → 4s → 8s … 上限 60s），连续失败 3 次状态进入 `error`，侧栏状态行显示「连接中断，正在重试」（没有独立的顶部离线状态条）。
7. 解析在**主进程**完成。同步时按 BODYSTRUCTURE 精确取正文块（`text/plain` / `text/html`）解码落库；点开邮件时缺正文也走同一条 BODYSTRUCTURE + part 路径并取回内嵌图，不再使用 `source.maxLength` 整封兜底。
8. 并发限制：同一账户的同步队列严格串行；正文下载另开最多 3 条连接（`MAILDESK_BODY_CONCURRENCY`，服务器拒绝时自动退回单连接），附件下载走独立连接，都不进同步队列。多账户可并行。
9. **双向对账**（启动时一次 + 每 3 分钟一次，`reconcileAccount`）：每轮只扫 STATUS 快照有变化的文件夹，深度轮次（每 5 轮，约 15 分钟）才枚举全箱 UID 与本地比对，抹平两侧差异：
   - 服务器有、本地无 → 补拉（头部 + BODYSTRUCTURE，正文同批预下载）；
   - 本地有、服务器无 → 服务器已删或已移走：若别的文件夹出现同 `Message-ID` 的邮件，用 `moveMessageRow` **认领**本地旧行（id、正文缓存、已读态全部保留），否则删本地行；
   - 服务器已读标志与本地不同 → 回写本地（刚点过、还在 `pendingFlags` 队列里的跳过，避免被旧状态覆盖）；
   - 每个文件夹上限 20 000 封，超过则跳过并 `logger.warn`。
10. **启动顺序**：`refreshFolders → reconcileAccount → syncAll`。必须先对账再增量，否则被网页版/手机 MOVE 走的邮件会被 `syncAll` 当新邮件重新插一行、旧行再被对账删掉（实测丢过 id）。
11. **文件夹也双向**：`refreshFolders`（LIST + STATUS + 增删）只在进程首轮、手动同步或距上次刷新满 15 分钟时执行，其余 3 分钟对账只问收件箱 STATUS；服务器上已经不存在的文件夹（网页版/手机端删除）连同本地邮件一起删掉（`deleteFolder` 先显式 `DELETE FROM message WHERE folder_id = ?`，因为外键级联删除不触发 message 的 `AFTER DELETE` 触发器，FTS 会留残影），并打 `[sync] folder removed <email> <path>`。侧栏当前选中的文件夹若被删掉，文件夹清单刷新后
12. 增量拉取偶发取不到某封的头部时（QQ 存在这种"幽灵 UID"），`last_synced_uid` 仍会推进；该封由下一轮对账补回，不靠游标回退。
13. **附件尺寸必须取自 BODYSTRUCTURE，不能取自被截断的正文**：正文预下载只取正文与内嵌图片 part，真正的附件二进制不在同步时传输；兜底路径 `fetchBody` 只取整封前 512 KB，截断后的附件 `size` 只是残片长度（实测 40 MB 的附件报 369 KB），所以两条路径都用 `collectAttachmentParts()` 各 part 的 octets 覆盖尺寸；base64 要按 76 字符一行折算（`(size − 行数×2) × 3/4`），直接乘 0.75 会偏大 3%（40 MB 显示成 41.1 MB）。
    - 口径差异（不是 bug）：列表「大小」列是整封信的 RFC822 字节数（`envelope.size`，含 base64 膨胀与全部头部），附件 chip 是解码后的文件大小，两处数字本来就不会相等。
14. **永久删除（EXPUNGE）必须复查结果**：QQ 对多 UID 的 `UID STORE +FLAGS \Deleted` / `EXPUNGE` 不可靠——实测一次删 3 封只掉 1 封，函数不报错，剩下 2 封留在服务器上；本地行却已经删掉，下一轮对账又把它们拉回来，用户看到的就是「全选后只删了一条」。所以 `purgeByFolder` 先整批 `messageDelete`，再按 UID `fetch` 复查一次，把剩下的**逐封补删**，最后只对确认消失的邮件删本地行，并把没删掉的数量计入 `failed`（界面据此提示「删除失败 · 服务器拒绝了其中 N 封」）。

**验收标准**：
- [ ] 新邮件到达 ≤ 3 s 内出现在列表顶部（IDLE 生效）。
- [ ] 手动修改服务器 `UIDVALIDITY`（模拟）后，客户端日志出现重同步且数据不重复。
- [ ] 拔网线 1 分钟后恢复，自动重连并补齐期间邮件。
- [x] 历史回溯：把本地 INBOX 最早的 100 封删掉后后台自动补回（隔离库实测 373 → 473，服务端 474）。
- [x] 服务器删除 → 本地删除：网页版删掉一封后，下一轮对账日志 `removed 1`，本地行消失。
- [x] 服务器移动 → 本地认领：网页版把邮件移到子文件夹后日志 `moved 1`，本地行 id 不变、只改 folder 与 uid。

### FR-06 搜索（P1）

**规则**：
1. 标题栏中间**常驻**一个搜索组合胶囊（高 24px）：左侧是范围下拉（**发件人 / 收件人 / 标题 / 正文**），右侧是输入框；没有搜索图标入口，也不弹任何候选窗口/遮罩。`Ctrl+K` 或 `/` 把焦点送回输入框，`Esc` 清空关键词。

6. 切换文件夹或点击标签会清空关键词，列表回到该文件夹；搜索结果里移动/删除/标已读仍走同一条 IPC，永久删除与否按该封邮件自己所在的文件夹判断。

**验收标准**：

## 6. UI / UX 规范

### 6.1 设计方向：Quiet Light

方向代号 **"Quiet Light"**：**结构取 Mimestream**（三栏、去边框、大留白、胶囊切换，颜色只用于状态），**配色取冷中性应用壳**（Linear / SAP 谱系，2026-11-27 用户选定 A 方案）：标题栏/侧栏取 Win11 标题栏灰（`--background`）、画布纯白（`--card`）、墨阶三级、单一蓝（`--primary`）。**只维护浅色一个主题，不提供深色模式**（2026-11-24 决定）。

1. **去 chrome**：不使用分割线、Ribbon、App Rail。层级只靠背景明度、字重与留白表达。
2. **明度分层**：标题栏/侧栏 → 画布 → 浮面 → 选中，靠明度差表达层级，不堆边框；大面积不使用纯黑。
3. **字重优先于颜色，明度分层表达已读**：未读/已读先靠 `600` 与 `400` 区分，再让已读行整体暗一档，**用实色 token 而不是透明度**（2026-11-27 定稿）：发件人 / 主题 / 日期 / 大小用 `--ink-read`，摘要与时间用 `--ink-faint`，状态圆点用 `--dot-read`，头像 `opacity-60`，未读行保持纯 `--foreground`。透明度会在 hover / 选中底色上二次合成，同一行在不同底色下颜色不一致，不要再改回 `foreground/65` 这类写法。颜色仍只留给品牌蓝与状态，不要给已读行染灰蓝色调。
4. **克制动效**：仅用于状态变化，120–160 ms `ease-out`，只动 `opacity` 与 `transform`；浮层用 `elevation-menu` / `elevation-dialog` 两层软投影，画布本身仍然无阴影无描边。

### 6.2 设计 token

沿用 shadcn 的语义变量体系（CSS variables + Tailwind v4 `@theme inline`），只做取值定制：

| Token | 值 | 用途 |
| --- | --- | --- |

**取色依据**：浅色单主题。外壳取 Win11 标题栏灰（`--background`，冷中性，2026-11-27），画布纯白（`--card`），墨阶 `--foreground → --muted-foreground → --ink-faint`，线条两级 `--border`（结构）与 `--table-line` / `--row-line`（表格 / 行，2026-11-27 统一），蓝色只出现在选中 / 未读 / 主按钮 / 焦点。层级靠明度差 + 浮层软投影表达，画布本身不画边框、不加阴影。`globals.css` 不再保留 `.dark` 分支。

**为什么换掉 QQ 浅蓝灰**（2026-11-27）：`#E6EDF5` 是带明显蓝色倾向的网银/网页邮箱口径，整块铺开后压住了内容，也让蓝色强调失去对比；换成冷中性灰后，白画布与蓝色状态才成为唯一的视觉重点。旧口径（QQ 浅蓝灰、`#F3F4F6`/`#DBEBFD` 两色交互、`#CDCDCD` 结构线）已废弃，不要再改回去。HTML 正文仍是文本优先、直接落在画布上（只在邮件自带浅色底/底图时保留原底色），数据表单独铺白底。

**文本选择**：应用外壳（侧栏、标题栏、列表、筛选标签、工具条）一律 `user-select: none`，划选不会把「未读 / 有附件」这类标签刷成蓝色；阅读器 `article` 与 HTML 正文 iframe 保持可选中（复制正文是刚需），表单控件 `user-select: text`。图片与链接同时禁止 `-webkit-user-drag`，避免拖出幽灵图或误触发导航。

**字体栈**：UI 用 `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif`；正文同栈；等宽用 `"Cascadia Code", "JetBrains Mono", monospace`。时间、未读数等数字一律 `font-variant-numeric: tabular-nums`。

**具体规则**

1. **选中行**：浅蓝 `--row-selected` 填充。**紧凑视图铺满整行（`before:inset-0`，不圆角，2026-11-27 用户要求）**；标准视图仍用**左右内缩 4px（`before:inset-x-1`）、上下内缩 2px 的圆角伪元素**画（不铺满整行；hover 同理用 `--row-hover`）。主/次级文字保持正常的已读与未读深浅（**不转白**）；行高不变，不做缩放。
2. **悬停**：列表 / 菜单 / 按钮统一用 `--row-hover`，选中统一用 `--row-selected`；**侧栏文件夹项例外**：hover 用中性灰 `--nav-hover`（2026-11-27 用户要求，灰底上 `--row-hover` 看不出且偏蓝），选中仍与列表同色。不位移、不加阴影。**标题栏控件例外**：☰ 账户菜单、折叠 / 列表视图 / 下载 / 窗口三键的 hover 用 `foreground/10`。
3. **阅读器正文**：直接落在白色画布上，不套卡片、不画外框；左右内边距 24px、上 20px / 下 16px。**阅读器上方没有 44px 空白带**——44px 是文档页签栏；页签栏下缘的 1px `--table-line` 就是阅读区与列表共用的上边线（2026-11-28 与实现对齐）。**页头与正文之间有一道 1px 分隔线**（`--table-line`，只在正文存在时出现；线到页头 16px、到正文首行 16px，2026-11-24 用户要求），HTML 内容按文本优先渲染。
4. **列表行之间不画线**，标准视图靠 6px 垂直间距与留白分隔（紧凑表格有 1px `--row-line`）。
5. **分割线**：仅在列表与阅读器之间保留 1px `--table-line`（**顶部 44px 不画**，竖线从第一根横线开始，2026-11-27 用户要求）——它就在白色画布内部，用结构线会显粗；画布外框、浮层描边用 `--border`；侧栏与画布之间用明度差区分，不加线。
6. **标签胶囊**：统一用 `--primary` 15% 底 + 主色文字，高 20px，圆角 999px（标签数据没有颜色字段，不按标签色着色）。
7. **头像**：首字母（英文取首字母大写，中文取首字）+ 由名字 hash 出的固定底色，白字 600。色盘 8 色：`#6D5AE6 #2F9E6E #E08A3C #2E6BFF #C0567F #23879B #A855C7 #B08A3E`，同一个人永远同色。尺寸随场景：列表 28px、阅读器 32px；紧凑视图是表格式单行，不显示头像。列表未读态在行首占用 6px 蓝点槽位（点 + 8px 间隙），蓝点与下方主题、摘要左对齐，发件人名字随之后移 14px；已读行不占槽位，发件人直接与主题、摘要左对齐。**选中行只换底色**：头像、蓝点、文字颜色都不变（2026-11-24 起不再转白）。
8. **滚动条是浮层，不占内容宽度**：容器加 `scrollbar-overlay` 隐藏原生滚动条（原生条会让列表、阅读器、Dialog 的内容区凭空窄 8px，并逼着列头去补让位），由 `OverlayScrollbar` 画一条 6px 宽、距右缘 3px 的固定细条浮在内容之上；**纵向条**滚动或鼠标进入时出现、停止 700ms 后淡出；**横向条**只要容器有横向溢出就常驻可见（2026-11-25 用户要求，配合「原版式」正文超宽可横滚，不靠悬停猜哪里能滚）；两条都可拖动；无轨道背景、无箭头、无两端按钮。列表、侧栏文件夹、设置、账户、搜索面板、发件人抽屉、收件人列表统一走这一套；**阅读器正文例外，用原生滚动条**（2026-11-25 用户要求）：容器加 `.scrollbar-native`，6px、透明轨道、圆角 thumb，外观照列表的浮层细条，但占位与行为保持原生；**纵向 thumb 静止时隐藏、滚动后 700ms 内或悬停时出现，横向条常显**。
9. **画布区（列表 + 阅读器）是一整块白色画布**（2026-11-24 用户要求；2026-11-27 改成零边距）：`App.tsx` 用 `mt-0 mb-0 ml-0 mr-0 flex min-w-0 flex-1 flex-col overflow-hidden border-t border-border bg-card` 包住文档页签栏 → 列表 → 分隔线 → 阅读器（侧栏展开时再加 `border-l border-border`）：**四周边距全为 0**，贴住标题栏下沿、侧栏右缘与窗口右/下边缘，**侧栏收起时左边同样是 0**；**侧栏展开时左上角保留 `rounded-tl-lg` 圆
10. **空状态**：居中，32px 图标 + `--muted-foreground`，一句文案（没有主按钮），不使用插画。**演示数据只在 dev 构建存在**（`lib/mock.ts` 由 `import.meta.env.DEV` 门控，正式包的 fixtures 会被摇掉）：正式包一个账户都没有时，列表空状态固定显示「还没有配置账户 / 点标题栏左上角的 ☰ 菜单 →「添加账户…」添加你的 IMAP 邮箱」，侧栏不显示「标签」分组，底部同步文案显示「尚未连接账户」——不出现任何演示邮件或假同步状态
10.5 **关闭窗口的行为可配置**：默认点窗口 × 直接退出；开启「关闭窗口时最小化到托盘」后，`close` 事件只 `hide()` 窗口（不退出、不销毁），托盘图标与未读角标继续工作，点托盘图标或菜单「打开 MailDesk」恢复窗口，只有托盘菜单的「退出」（或 `app.quit()`）才真正退出——主进程用 `before-quit` 置 `quitting` 标志放行 close，避免退出时被拦成隐藏。
10.7 **下载管理**：标题栏窗口三键左侧有「下载」按钮，点击弹出 320px 浮层（`ui/popover` 的 Radix Popover，**用组件默认样式**：`rounded-md`、`p-4`、`elevation-menu`，与标题栏间距 12px），列出本次运行内的附件下载（进行中排前、最近完成最多 20 条）。进行中的显示进度条与百分比、可点 × 取消（主进程销毁 IMAP 下载流）；**已完成且已落盘的显示「打开文件夹」按钮**（`shell.showItemInFolder` 定位到文件）；失败/已取消显示状态。图标右上角有小圆点表示有进行中的下载；点浮层外或 Esc 收起。
11. **标题栏自绘且承载功能**：窗口 `frame: false`，无系统标题栏与系统按钮。标题栏高 36px（2026-11-27 用户要求从 44px 减小，`h-9`），整条同色，从窗口最左缘开始排：**最左是 ☰ 账户菜单，紧跟侧栏折叠开关**（2026-11-27 用户要求，取 OpenCode 的左上角样式），再依次是「列表视图 + 搜索 + 拖拽留白 + 下载 + 窗口三键」——搜索与列表视图紧贴折叠开关靠左，中间整段留给拖动窗口，形成「每个平面一直顶到窗口上沿」的连续感，不做横向色带、不加下边框。标题栏**不重复显示列表标题与未读数**（列表自己的标题行与页签已给出），也**不把列表/阅读器的分隔线延伸进标题栏**。设置入口不在标题栏，只在侧栏底部。
    - 因为这条 36px 已被功能占满，**列表不再有独立的标题行与搜索行**（原 52px 标题行 + 40px 搜索行、以及筛选行都已删除），列表从文档页签栏下方开始，纵向多出约 90px 给邮件。
    - 最小化 / 最大化悬停用 `foreground/10`，关闭键悬停填充 `#C42B1C` + 白图标；三个按钮各 46×36px，图标 10px 1px 描边。窗口缩放边框、Aero Snap、双击最大化仍走 Windows 原生行为。

**落地要求**：
1. 使用 `npx shadcn@latest init` 并选择 **Vite** 模板（非 Next.js）。
2. `components.json` 配置：`"rsc": false`、`"tsx": true`、别名 `@/components`、`@/lib/utils`。
3. Tailwind **v4**：通过 `@tailwindcss/vite` 插件接入，入口 CSS 使用 `@import "tailwindcss"` + `@theme inline`，不再生成 `tailwind.config.js`（除非需要内容扫描例外）。
4. 图标统一用 `@phosphor-icons/react`（2026-11-27 从 lucide 换成 Phosphor），不混用其他图标库；**全应用默认 `weight="bold"`**（`main.tsx` 的 `ICON_DEFAULTS`，用户选定），需要实心态时用 `weight="fill"`（如置顶图钉），个别图标想细一点可以单独覆盖 `weight="regular"`。
5. **只有浅色主题**，不引入 `next-themes`，也没有主题切换逻辑；`html` 的 `color-scheme` 固定 `light`。
6. 允许直接用 shadcn 的 **dashboard block**（如 sidebar 系列）作为起点，但需清理演示内容。

输入框聚焦时普通按键失效，带修饰键的组合仍可用；但输入框内的 `Ctrl+A` 保留系统「全选文本」，不触发邮件全选。

### 6.6 状态设计（每个页面必须覆盖）

| 状态 | 表现 |
| --- | --- |
| 初始加载 | 骨架屏（行占位，不显示转圈） |
| 空 | 32px 图标 + 一句说明（无账户时提示从 ☰ 菜单添加，没有主按钮、不用插画） |
| 错误 | 错误原因 + 重试按钮 + 展开详情 |
| 离线 | 未实现独立离线条：侧栏状态行显示「连接中断，正在重试」，列表仍显示本地缓存 |
| 同步中 | 状态栏小圆点脉冲，不阻塞交互 |
| 操作失败 | 窗口底部居中一次性提示条（红色警示图标 + 一句话原因，3.5 s 自动消失），不弹对话框、不打断阅读 |
| 部分失败 | 单账户失败不影响其他账户，账户项显示警示图标 |

### 6.7 无障碍

- 所有可点击元素需有可见焦点环（`:focus-visible`）。
- 对话框使用 Radix 自带焦点陷阱与 `Esc` 关闭。
- 列表使用 `role="listbox"` / `option`，支持键盘导航与 `aria-selected`。
- 文本对比度 ≥ 4.5:1。

| 列表虚拟化 | @tanstack/react-virtual | 必选 |

| 编码兜底 | iconv-lite | GBK/GB2312/GB18030 |
| 本地库 | **node:sqlite**（Electron 内置 Node 24）+ FTS5 | 同步 API、零原生依赖，不需要 electron-rebuild / asarUnpack；FTS5 已实测可用（SQLite 3.54） |

| HTML 清洗 | dompurify | 渲染前清洗 |
| 代码质量 | TypeScript strict + `npm run typecheck` + vitest（解析 / 分组 / 格式化 / 迁移） | 未配置 ESLint / Prettier，靠 tsc、单测与构建兜底 |

### 7.2 关键取舍与 shadcn 适配注意

1. **不用 Next.js**：shadcn 文档默认给 Next 示例，必须按 Vite 路径安装；组件本身与框架无关，但 `"use client"` 指令可删。
2. **Tailwind v4 的 `@theme inline`** 决定 token 写法；只保留一套 `:root` 浅色 token，不维护 `.dark`。
3. **Electron 的 `file://` 限制**：`base: './'`、HashRouter、避免绝对路径资源。
4. **Radix Portal 与多窗口**：Electron 单窗口下正常；若引入独立阅读器窗口需重新挂载 Portal 容器。
5. **字体**：不用 `next/font`，直接使用系统字体栈或 `@fontsource` 本地包（离线可用）。
6. **数据库不引原生模块**：Electron 45 自带 Node 24，`node:sqlite` 提供同步 API 且内置 FTS5，直接 `import { DatabaseSync } from "node:sqlite"` 即可，省掉 `electron-rebuild`、`asarUnpack` 与 Windows 编译链。代价是绑死 Electron 自带的 SQLite 版本；若将来需要更新的 SQLite 特性，再换回 better-sqlite3（届时按 ABI 重新构建）。

### 7.4 数据模型（SQLite）

| 表 | 职责 | 关键约束 |
| --- | --- | --- |
| `account` | 账户与 IMAP 参数 | 密码不进此表 |
| `folder` | 服务器文件夹 + 同步游标 | `UNIQUE(account_id, path)`；`uid_validity` / `uid_next` / `last_synced_uid` / `backfill_uid` / `enabled` |
| `message` | 邮件头 + 正文 | `UNIQUE(folder_id, uid)`；`body_text`（搜索 / 纯文本）、`body_html`（原始 HTML） |
| `message_fts` | FTS5 全文索引 | external content，增删改由触发器同步 |
| `attachment` | 附件元数据 | 二进制不进库；`part` 记 BODYSTRUCTURE 号；内嵌图不算附件 |
| `credential` | 账户凭据：优先 `safeStorage`（DPAPI）加密；不可用时降级明文并在 `scheme` 标 `plain` |
| `setting` | key/value JSON | 替代 electron-store |

- 精确列定义与迁移以 `src/main/db/schema.ts` 为准；表身份、事务、搜索路径与迁移纪律见 [docs/data-model.md](data-model.md)。
- 迁移：`PRAGMA user_version` 作下标，`MIGRATIONS` 只追加、不改历史项，每条单独事务。
- 存储：正文随同步入库，点开不再联网；附件只存元数据，保存/预览时按 part 下载；库开 WAL。

### 7.6 同步状态机

    disconnected → connecting → selecting(folder) → fetching(uid range)
        → idling ⇄ (EXISTS → fetching → idling)
        ↑                                        │
        └──── backoff(2s,4s,8s,…,60s) ←── error ─┘

规则：
- 每个账户一个 `SyncEngine` 实例，内部串行队列。
- 首次同步：`UID FETCH (uidNext-limit):* (ENVELOPE FLAGS INTERNALDATE RFC822.SIZE BODYSTRUCTURE To Cc)`，其余历史由回溯补齐。
- **正文预下载**：列表与正文都在本地库里，点开任何一封都不再发 IMAP 请求；缺失正文的老数据由 `bodyBackfillLoop` 启动后补齐，`fetchBody` 只剩兜底作用。
- 收到 `EXISTS` 后按 `last_synced_uid+1:*` 增量，不重复解析已有 UID。
- 所有失败写入 `SyncStatus.error` 原始文案并记日志；IPC 层错误才归一到 `ErrCode`（network / tls / auth / unsupported / db / internal / bad-request / not-found），界面只展示错误码与一句话说明。
- `UIDVALIDITY` 变化：清空本地数据并重置游标，先重拉最新窗口，剩余历史由回溯补满整箱。
- 正文块必须按 `Content-Transfer-Encoding`（base64 / quoted-printable）还原后再按 charset（`iconv-lite` 兜底 GBK/GB2312）解码；摘要由解码后的纯文本生成，否则中文摘要会变成乱码。

## 8. 非功能需求

### 8.1 性能

- 列表虚拟化；整箱一次载入（本地库已是全量），任何操作不阻塞 UI 线程。
- 正文只按 BODYSTRUCTURE 取需要的 part；单张内嵌图 >10MB 不内嵌（透明占位）；正文链默认 3 条连接（`MAILDESK_BODY_CONCURRENCY`，服务端拒绝时退回 1 条）。
- 数据库操作全部走事务批量写入（每批 50 封）。
- 启动时只加载窗口位置与账户列表，不阻塞等待网络。

### 8.2 安全与隐私

- 密码 / token 优先用 `safeStorage` 加密存储；加密不可用时降级明文并标记 `plain`。
- 远程图片默认**放行**，用户可在设置里改为拦截；拦截态注入 CSP 阻断外部图片 / 字体 / 追踪像素。
- 不接入任何统计、崩溃上报、遥测。
- `shell.openExternal` 仅允许 `http/https/mailto/tel`。

### 8.3 体积与分发

- 安装包目标 < 120 MB（Electron 基线约 80–100 MB）。
- 仅提供 Windows x64 免安装 **portable exe** + NSIS 安装包（`electron-builder.yml` 的 `nsis` / `portable` 两个 target，无 zip）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 原生模块编译失败 | 阻塞 M2 | 已规避：改用 Electron 内置 `node:sqlite`，无原生编译 |
| 国内邮箱（163/QQ）IMAP 限制 | 收不到信 | 内置 IMAP ID、授权码引导、常见错误码映射；QQ 需在网页端开启 IMAP |

| 大邮箱首次同步慢 | 首启体验差，正文全量下载更占带宽 | 首屏只等 200 封；历史与正文由后台 `backfillLoop` / `bodyBackfillLoop` 分批补，不阻塞交互 |

| Electron 内存偏高 | 常驻体验差 | 单窗口、限制缓存、关闭 DevTools、必要时 `backgroundThrottling` 调整 |
