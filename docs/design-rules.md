## 设计约束（摘自 PRD 6.x，改之前先读原文）

- 三栏固定结构：侧栏 220（可整体收起：收起后侧栏不渲染、不保留图标栏）/ 列表 380（可拖 320 ~ 窗口宽度的一半，上限随窗口缩放）/ 正文满宽居中。无 App Rail、无 Ribbon。
- **组头条吸顶**：`MessageList` 用「高度 0 的 `sticky top-0` 容器 + 绝对定位的 24px 组头条」实现，不占滚动高度；当前组由 `groupAnchors`（按 `groupRowHeight`/`rowSlot` 累加的组起点）和 `scrollTop` 计算，切组时才 `setState`（用 `stickyKeyRef` 挡住滚动中的重复渲染）。不要改成给虚拟行加 `position: sticky`——虚拟行是 `absolute + translateY`，sticky 不生效；也不要把吸顶条塞进虚拟内容里，否则会跟着内容滚走。
- **置顶（2026-11-25 用户要求，取代「星标置顶」）**：右键「置顶」/`S` 复用 `message.starred` 这个数据库列作为置顶标记（列名不改，UI 上一律叫「置顶」，不要再出现星标文案/星标图标）；`MessageList` 在构建 `rows` 时先把 `messages.filter(m => m.starred)` 摘出来，**不参与 `groupByDay`/`groupBySize`**，拼成一个 `{ key: "group-pinned", label: "置顶" }` 组放在最前（折叠 key 也是 `group-pinned`），其余邮件照常分组。置顶组同样参与吸顶与折叠；取消置顶后回到日期分组。紧凑表格里已经删掉星标列（`COL_STAR` 不再存在，`COL_FIXED = 26 + 18`）。
- **文件夹可见性由用户选择**：`folder.enabled`（schema v8，默认 1）决定侧栏是否显示与是否参与同步。侧栏底部「选择文件夹」打开 `FolderPickerDialog`，走 IPC `folders:scan`（`engine.scanFolders` → `refreshFolders`，会真实连服务器）与 `folders:set-enabled`（`setFolderSelection`，收件箱强制启用，保存后 `syncNow`）。`syncAll` / 回溯 / 对账 / 正文补齐 / 托盘未读数都只算 `enabled = 1`；`refreshFolders` 仍然 upsert 全部服务器文件夹，但**不能覆盖已有的 `enabled`**（新发现的系统文件夹默认开、自建文件夹默认关）。App 侧过滤时要保留启用文件夹的祖先容器（否则「其他文件夹」分组会消失、子项缩进悬空），见 `visibleNavList()`：必须先用完整文件夹清单跑 `navFolders` 再过滤，否则只剩容器时会被当成可选中的顶层文件夹，多出一个「其他文件夹 > 其他文件夹」；容器没有可见子项时连分组一起收掉。
- **侧栏 = gap（占位）+ 绝对定位面板**（2026-11-27 定稿，参考 shadcn「Peek & Pin」与 OpenCode `sidebar-peek`）：
  - gap 是一个空 div，宽度 `collapsed ? 0 : 220`，挂 `transition-[width] duration-200`；**画布的左右移动只由它驱动**。
  - 面板（同一个 `Sidebar` 实例，不卸载，折叠状态与滚动位置不丢）永远是 `absolute inset-y-0 left-0 z-30 w-[220px]`，靠 **`transform: translateX(-100%) ↔ 0`** 进出，`transition-transform duration-200`。
  - peek：只把 transform 归 0，gap 仍是 0 → **画布一帧都不动**，而且 transform 走合成器，列表不重绘（这解决了「收起时列表抖一下」）。
  - 停靠（抽屉开着点按钮）：`collapsed` 变 false → gap 0→220 过渡、面板 transform 本来就是 0 → 画布从面板下方平滑右移，结束时两者恰好重合，**没有二次交接**。
  - 收起：gap 220→0 与 transform → -100% 同时跑，两个边缘始终重合。
  - 描边/投影只在 `collapsed && peek.peeking` 时加（抽屉状态收在 `hooks/use-sidebar-peek.ts` 的 `useSidebarPeek`）：**上边 + 右边各 1px `--border`**（上边把抽屉和标题栏分开、并与画布顶边接成一条；右边把抽屉和列表分开）+ `elevation-menu`。这两条线必须用**面板内绝对定位的 1px div**（`inset-x-0 top-0 h-px` / `inset-y-0 right-0 w-px`，`pointer-events-none`）画，**不能用 `border-t border-r`**：border 会占掉面板内侧 1px，从抽屉停靠成展开时边框消失、侧栏内容会突然上移+右移 1px，用户会看到「抖一下」（2026-11-27 实测反馈）。展开时只靠画布自己的左边框，面板再画一条会变 2px（实测过）。
  - 面板滚动条用 `showScrollbar={!collapsed}`：收起/peek 时它的浮层滚动条是 `fixed` + portal，会停在原地扫过列表。
  - 指针离开按钮后 180ms 再收（按钮在标题栏、面板在内容行，中间隔着几像素），面板自己的 `onMouseEnter` 取消定时器；在面板里选文件夹/标签会直接收起。**不要再加 `w-[50px]` 的窄栏**，也不要恢复「只显示系统文件夹」这类折叠分支（`Sidebar` 没有 `collapsed` prop）。画布左边距恒为 0（收起时也不再补 7px，2026-11-27 用户要求），所以不存在 `margin-left` 过渡。标题栏左段同时 `220 → 170`（固定值，宽度可过渡；胶囊 `truncate`），别留 220px 空档、也别用 `width:auto`（不可过渡）。动画期间（260ms 兜底定时器）调 `drag-pause` 的 `setDragging(true)` 冻结正文测量，结束后自动补量一次——否则 iframe 宽度每帧都变，长邮件会整篇重排。侧栏底部的同步状态行、设置、选择文件夹随侧栏一起隐藏，手动同步走 `Ctrl+R`。持久化 key 仍是 `maildesk.sidebarCollapsed`（语义从「窄栏」变成「整块隐藏」）。
- **只有浅色一个主题**（2026-11-24 决定，深色模式已删除）：侧栏/标题栏 `--background`、列表/阅读器画布 `--card`、浮面 `--muted`、hover `--accent`、选中 `--row-selected`、结构线 `--border`、主色 `--primary`。不要再添加 `.dark` token、`dark:` 分支或深浅切换入口；`theme.tsx` 只负责把 `--background/--foreground` 同步给窗口底色。
- 画布区（列表 + 阅读器）由 `App.tsx` 里的一个容器统一做成一整块白色画布：`mt-0 mb-0 ml-0 mr-0 border-t border-border bg-card overflow-hidden`——**四周边距全部为 0**，贴住标题栏下沿、侧栏右缘与窗口的右/下边缘（2026-11-27 用户要求把原来的 7px 边距收成 0，侧栏收起时左边也是 0）；**侧栏展开时左上角保留 `rounded-tl-lg` 圆角**（2026-11-27 用户要求：那里贴着侧栏，露一点 `--background` 是正常的卡片观感）；**侧栏收起时四角全直角**（左侧已经贴窗口，圆角会在角上露出背景缺口），右上/右下也一直是直角；**只保留上边一条 1px `--border`**（标题栏下沿与画布上沿共用这一根线）。**右 / 下两条边不画边框**（2026-11-27 用户要求：贴边后 1px 落在客户区最外一像素上、肉眼基本看不见）；**左边缘只在侧栏展开时画 1px `border-l`**（把画布和侧栏分开，`!collapsed && "border-l border-border"`），**收起贴窗口时不要**（窗口边框本身就是边界）。不要再给右/下补 `border-r/b`，也不要把 `border` 整个加回来。不加阴影；列表 `section` 只负责 `bg-card`，**不要**再给它加 `rounded-*` / `overflow-hidden` / 边框，否则会和画布叠成双份。
- 层级靠明度差，不靠边框堆叠；列表与阅读器之间只保留 1px `--table-line`。
- **列表内部的表格线统一用 `--table-line`**（列头 `border-y`、列分隔 `border-r`、组头/行 `border-b`），不要在 `border-border` 上套 `/40`、`/60` 分档——档位在浅色下几乎看不出差别，用户要求「彻底统一」（2026-11-22）。**行的横向分割线用 `--row-line`（与 `--table-line` 同值，2026-11-27 统一）**（`after:bg-row-line`），行线左右铺满到卡片左缘与列表/阅读器分隔线；列表与阅读器之间的 1px 分隔线（`App.tsx` 拖拽把手里的 `bg-table-line`）也用 `--table-line`，不再用 `--border`；画布外框 / 浮层描边用 `--border`。**弹窗内部的分隔线同样用 `--table-line`**（账户/文件夹选择/设置/同步状态四个弹窗的头部分隔线、底部按钮条、设置左侧分栏、设置项之间的分隔线（2026-11-28 用户先要求加深一档，实测 `--border` 偏蓝且深 25 级，改为中性叠层 `divide-foreground/[0.06]`，合成后比卡片底色深约 13 级）、同步面板的区块线），只有弹窗外框保留 `--border`——弹窗底色是纯白 `--popover`，`--border` 的 1px 全宽长线在那里会显得比圆角边框粗一档（2026-11-26 用户反馈「账户下方那条线看起来粗」），不要再改回 `border-border`，也不要给这些线套 `/60` 分档。**列头的竖向分隔线用 `.col-sep` / `.col-sep-l` 伪元素画**，`top/bottom: 0` 上下贯通、与列头的横线相交（2026-11-27 用户要求；2026-11-24 曾要求内缩 6px 不相交，已改回），不要再用 `border-r`。紧凑列头的底色用 `bg-card`（纯白，2026-11-27 用户要求），不要再回到 `foreground/[0.05]` 的灰底。
- **浮层投影只有两档**（2026-11-27 新增，`globals.css` 的 utilities）：`elevation-menu` 给下拉 / 右键菜单 / Popover / 发件人抽屉 / Toast，`elevation-dialog` 给弹窗；menu 是 `0 1px 2px rgba(16,24,40,.06) + 0 10px 28px -10px rgba(16,24,40,.18)`，dialog 再多一层大范围扩散。**画布本身仍然无阴影**（外圈那 1px 是 `--border` 描边，不是投影），列表、行、卡片内容块也不要套投影。
- **居中弹窗按整数像素定位**：`DialogContent` 在挂载、窗口缩放与内容改高时，用 `offsetWidth/Height` 和 `window.innerWidth/Height` 算出整数 `left/top` 并写入，同时把 `translate` 设为 `none`；不要用 `top: 50% + translate(-50%)` 直接居中——半像素位置会把 1px 标题线抗锯齿成两行（2026-11-28 像素取样实测），窗口缩放时用 rAF 合并重算。
- 侧栏文件夹项：hover 用**中性灰** `--nav-hover`（2026-11-27 用户要求，灰底上原来的 `--row-hover` 既几乎看不出、又偏蓝）、选中 `--nav-selected`（与列表同色）（圆角 `rounded-md`，不要在选中行再加边框）；12px、字色 `--foreground`、分组标题 `font-medium`、**选中项 `font-bold`（700，`font-semibold` 用户看不够粗）**；计数角标 11px **未选中 `text-muted-foreground`、选中 `text-nav-count-active`（与主色统一）**（2026-11-27 起取消橙色 `text-star` 与 QQ 的旧强调蓝）。**默认（系统）文件夹与自建文件夹之间有一道 1px 分隔线**（2026-11-27 用户要求）：`navFolders()` 把 `dividerBefore` 挂在第一个自建项上（通常是「其他文件夹」分组标题），`Sidebar` 渲染成 `<div className="mx-2 my-1.5 h-px bg-border">`——左右各内缩 8px、颜色取 `--border`（`--table-line` 在灰底上太淡）；没有自建文件夹时不画，分组折叠时线仍在。
- 未读/已读先靠字重（600 / 400）区分，再让已读行整体暗一档，**用实色 token 而不是透明度**（2026-11-27 改）：发件人 / 主题 / 日期 / 大小 `text-ink-read`、摘要与时间 `text-ink-faint`、状态圆点 `bg-dot-read`（hover `bg-ink-faint`）、头像仍是 `opacity-60`；未读行保持纯 `--foreground`。原来的 `foreground/65`–`/70` 会在 hover / 选中底色上二次合成、同一行在不同底色下颜色不一致，不要再改回透明度，也不要改回 `/85`（反差不够）或压到 `/50`（太糊）。`--muted-foreground` / `--border` 保持现有取值；不要在列表里给已读行加别的颜色。
- 列表行交互色（2026-11-27 冷中性方案）：hover `--row-hover`、选中 `--row-selected`；**素底色都是伪元素**（紧凑 `before:inset-0`，**铺满整行、不圆角**，2026-11-27 用户要求；标准视图仍 `before:inset-x-1 before:inset-y-[2px] before:rounded-lg` 内缩圆角）；**选中行文字不变白**，仍按已读/未读用 `foreground` / `ink-read` 这一套深浅；未读点、高亮块在选中行也保持正常颜色。**不缩放**；动效只动 `opacity` / `transform`，120–160ms `ease-out`。
- **hover 与选中不能连成一块**（2026-11-28 用户再次指出，属于反复出现的错误）：圆角块状的可点项（侧栏文件夹、设置左侧分区、任何 `rounded-md` 导航列表）**不能 0 间隙紧贴**——选中的蓝块和相邻项的 hover 灰块会拼成一个大色块，看起来像同时选中了两项。容器必须给 `gap`（`gap-px` 是最低限度，`gap-0.5` / 2px 更稳），并且不要用负 margin、相邻 padding 之类的办法把块拼回去。表格行（整行铺满、无圆角、有 `--row-line` 分隔）不属于这一类，它们靠行线分隔，不需要额外 gap。
- **设置页的分组是「小标题 + 浅灰圆角卡片」**（2026-11-28 用户指定）：组标题 11px **600 字重**、`--muted-foreground`，在卡片外上方；卡片 `rounded-xl bg-foreground/[0.05]`，行与行之间用 `divide-y divide-foreground/[0.06]`（中性叠层，合成后比卡片底色深约 13 级；不要用 `--border`——偏蓝且深 25 级，也不要回到 `--table-line` 那样几乎看不见），**行自己不再画上下边框**（否则卡片里出现双层线）；卡片内左右 16px、行上下 12px。
- **分段控件用 shadcn `ToggleGroup`（`components/ui/toggle-group.tsx` + `toggle.tsx`）**：调用处套 `bg-foreground/[0.05]` 中性灰轨道（`rounded-md p-0.5 gap-0.5`，`size="sm"` 控制高度、item 左右内边距 8px，2026-11-28 用户要求再矮再窄一档），**组内必须留 2px gap**，否则选中白块和相邻 hover 块会贴成一块（同「hover 与选中不能连成一块」），选中项是**纯白药丸** `data-[state=on]:bg-card`、文字 `text-foreground`，未选中项 `text-muted-foreground`、hover `bg-foreground/[0.05]` + `text-foreground`（叠在轨道上比轨道深约 11 级，2026-11-28 按参考图补）；键盘方向键与 roving focus 交给 Radix，不要手写 `role="radiogroup"`。**选中与 hover 块自己四角都是 `rounded-md`**，不要用 `first:rounded-l-md / last:rounded-r-md` 的贴边圆角——那样中间项选中时是直角，和参考图的独立药丸不一致（2026-11-28 用户要求）。轨道**不要用 `bg-muted`**——`#ECEEF1` 带蓝调，和参考的纯中性灰不一致（2026-11-28 用户指出）。**不要把选中色改回 `--accent`**——它在灰色卡片上和底色只差 1~4 级，等于看不见（同日实测）；也不要用 `--row-selected` 淡蓝块，压在灰轨道上会发脏。
- **键盘焦点必须可见**：全局 `:focus-visible` 用 1px `--ring` 内描边（`outline-offset: -1px`），菜单项靠 focus 背景色、不叠描边；不要只写 `outline: none`。控件还要有可访问名称（手写开关传 `aria-label`，分段控件用 `ToggleGroup` 的 `aria-label`，键盘方向键由 Radix 处理）。
- 画布顶部是 44px 文档页签栏（`h-11`，下缘 1px `--table-line`），列表与阅读器共用这条上边线（2026-11-28 与实现对齐：阅读器没有独立的 44px 空白带）；阅读器 `article` 顶部 20px（`pt-5`）、左右 24px、下 16px。再往下才是头部：主题 → 发件人区（左侧头像；右侧两行：**第一行姓名 + 操作图标组**，**第二行邮箱 + 完整时间**）→ 标签 chip 与附件 chip（同一行 `flex-wrap`）→ 正文。图标组**最后一个**是「该发件人的全部邮件」抽屉（`PanelRight`）：右侧 320px `absolute` 面板，头部是发件人头像 + 姓名 + 邮箱 + 封数（不要写标题文案、不要放关闭按钮），点击抽屉外的透明遮罩收起（`fixed inset-0 z-10`，`onMouseDown`）；出入场用 `globals.css` 的 `.drawer-in`（160ms ease-out）/ `.drawer-out`（120ms ease-in forwards，延时 120ms 再卸载，`senderClosing` 状态控制），只动 `transform: translateX(16px)` + `opacity`，并带 `prefers-reduced-motion` 降级，数据用 `mail.search.query(fromEmail, { scope: "from", limit: 200 })` 再按 `fromAddr` 精确过滤、`summaryToMessage` 转成列表；抽屉每项只显示主题 + **完整时间**，不显示正文摘要（用户要求），**字色与列表同口径**：未读主题 `text-foreground`、已读主题 `text-ink-read`，时间未读 `text-muted-foreground`、已读 `text-ink-faint`（2026-11-27 用户要求，之前已读主题也是纯前景色、只能靠字重区分），点击项走 `App` 的 `onNavigate`（切文件夹 + 清搜索 + 选中 + 标已读）。**不要恢复独立的 52px 工具条**：图标必须在发件人行里，否则正文被压低 52px（用户要求「正文整体顶上去」）；`article` 用 `pt-5` 保留最小上留白。附件必须在首屏可见，不许沉到长正文下方。收件人/抄送姓名**必须读 To/Cc 原始头**（`headers: ["to","cc"]` + `parseAddressHeader`；QQ 的 ENVELOPE 只给地址本地部分，旧数据靠启动时 `refreshRecipientNames` 一次性修正）。展示上**不要用「、」拼全量地址**：折叠态 ≤3 人列全名，人多时「发给 甲、乙 等 N 人 · 抄送 M 人」并 `truncate`；展开态按「收件人 N」「抄送 M」分组；**每行只显示一位联系人**，姓名与地址同一行（姓名近黑、`shrink-0 whitespace-nowrap` 保持完整不省略；地址次要色、展示为 `&lt;address&gt;`，只有超长地址在括号内 `truncate`，括号本身始终保留；`title` 给完整 `姓名 <地址>`），不要按「/」拆段加粗/改色；单组最高 260px 内部滚动——公司邮件几十人起步（用户 2026-11-23 反馈）。
